# dlg-0082 逐轮对照（离线 vs LLM）

以后 bad case 可看 `turn_traces_latest.md`，或复跑：

```bash
python -m tripsense.eval --multi-turn --judge stub --ids dlg-0082
python -m tripsense.eval --multi-turn --llm --judge stub --ids dlg-0082
```

报告 JSON 里每条结果带 `turn_trace`（该轮用户话、系统回复、当时路线、当轮分数）。

---

## T1

用户：我打算明天去北京玩一天，早上9点出发，晚上6点前结束。我年纪大了，走不动太多路，想去些经典景点，比如天安门、故宫，还有公园什么的。

| | 离线 | LLM |
|--|------|-----|
| 系统 | 模板：先按描述整理一版 | 听懂经典+公园、放慢少走路 |
| **当时路线** | 天坛公园-斋宫 → 回音壁 → 祈年殿 | **广济寺 → 北京历代帝王庙** |
| 当轮 | Pass · theme 满分 | **挂** · 主题 0、偏稀 |

两边第一轮都没有天安门、故宫。LLM 连公园也没有。

## T2

用户：这个路线不错，但故宫太大了……去掉故宫，换成天坛这样的公园。

| | 离线 | LLM |
|--|------|-----|
| 系统 | 顺着这句话轻轻调一版 | 说要去掉故宫、换成天坛，但承认广济寺/帝王庙先留着 |
| **当时路线** | 仍是天坛园内三站（没故宫可删） | **仍是广济寺 → 帝王庙（天坛没加上）** |
| 当轮 | Pass | 挂 · 主题 0 |

脚本在问「去掉故宫」，实际线上从来没有故宫。

## T3（评测终局）

用户：下午两个公园有点赶……只去北海公园，早点结束。

| | 离线 | LLM |
|--|------|-----|
| 系统 | 再轻轻调一版 | 说下午只留北海、往北海收 |
| **当时路线** | **仍是天坛三站（北海没加上）** | **仍是广济寺 → 帝王庙（北海没加上）** |
| 当轮 | Pass · 主题仍因天坛算公园满分 | 挂 · 主题 0 |

---

离线三轮路线几乎没动，只是标签碰巧像「自然公园游」。LLM 从第一轮就偏到寺庙，后两轮口头答应换天坛/北海，线没改。这条 case 的对话假设和真实路线对不上，逐轮才能看清。
