# TripSense 上海数据完善方案

## 一、第一阶段地域范围

上海 MVP 只发布上海市16个行政区内的 POI。昆山、太仓、嘉善、常熟、启东、南通等周边数据不删除，统一进入 `nearby_city_phase2` 数据池，二期以“上海 + 周边城市”产品模式重新启用。

当前旧数据缺少 `adcode`，第一轮使用上海市官方16区名称过滤。重新调用高德时应保存 `pcode/pname/citycode/cityname/adcode/adname`，并优先用 `adcode` 判断地域。

## 二、数据源职责

### 1. 高德：实体与空间底座

保留 POI ID、父 POI ID、完整三级分类、行政区编码、入口坐标、AOI、地址、电话和导航信息。查询上海时必须使用上海 `adcode` 并开启 `citylimit`，详情字段使用完整扩展参数。

高德解决“这个地点在哪里、是什么实体、如何到达”，不负责回答深度文化和体验问题。

### 2. 上海政府与行业主管部门：权威名单

- 上海市文旅局：A级景区、博物馆、文保与公共文化场馆。
- 上海市绿化市容局：城市公园、森林公园及开放政策。
- 上海市公共数据开放平台：公共文化场馆、预约、客流和旅游主体数据。
- 各景区、博物馆和公园官网：内部导览、展馆、门票、预约、无障碍和开放信息。

这些来源用于确认实体存在、官方等级、父子结构和稳定事实。

### 3. RAG 编辑知识：体验与解释

对优先 POI 建立有来源的知识文档，包括历史、文化、建筑、体验方式、适合人群、游览强度、室内外、建议时长和组合路线。每条内容记录来源、发布日期、抓取时间和适用期限。

### 4. 实时工具：动态状态

天气、当日开放、预约余量、临时闭馆、客流和公共交通不写入稳定 RAG，通过工具调用实时获取；不可用时返回未知。

## 三、推荐服务最小字段

基础实体：`poi_id/name/type/typecode/address/admin_code/coordinates/rating`。

景区层级：`site_parent_id/site_parent_name/site_relation/site_role/site_level`。

知识引用：`knowledge_doc_ids/source_ids`。

动态状态不持久化为稳定事实，只保存带时间戳的短期缓存。

## 四、实施顺序

1. 严格上海范围过滤并隔离周边数据。
2. 重新抓取或回填高德 `adcode`、父 POI ID、入口坐标及完整分类。
3. 对齐文旅局A级景区、博物馆和公园官方名录，做实体去重与别名归一。
4. 核验父子景区层级，构建景区内部路线图。
5. 先为100—150个上海核心地点建设稳定知识文档。
6. 建立上海查询评测集，再接入向量检索和重排。
