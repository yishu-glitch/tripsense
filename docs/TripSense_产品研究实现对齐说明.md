# TripSense 产品研究实现对齐说明

## 产品北极星

TripSense 不是一次性生成行程的路线工具，而是一个贯穿出发前、游览中和游览后的旅行伙伴。

核心价值应固定为三个连续能力：

1. 规划：理解用户此刻的时间、体力、兴趣、同行人和旅行目的，生成可解释的路线。
2. 调整：在用户状态、时间和现场条件变化后，沿用已有上下文做局部修改或必要的全局重排。
3. 记录：保存实际到访、实际停留、跳过原因和现场感受，使一次旅行形成可继续使用的数据。

“智能”不等于全部交给大模型。“懂用户”也不等于只做情绪分类。产品需要同时理解显式需求、隐式状态、历史操作和当前旅程进度。

## 产品层与研究层的关系

### 产品层回答什么

- 用户现在适合怎样玩。
- 为什么推荐这些地方和这个顺序。
- 时间发生变化时应该怎么调整。
- 哪些建议可以忽略，哪些约束必须提示。
- 旅行完成后留下了哪些真实记录。

### 研究层回答什么

- 如何把模糊时间表达量化为不确定分布。
- 如何控制路线超时风险。
- 如何根据多轮表达更新偏好状态。
- 如何比较固定偏好、规则更新和卡尔曼追踪的效果。

### 正确的依赖方向

产品层调用研究模型提供的能力，但保留确定性规则、人工可解释约束和安全降级方案。CCP、DRCCP 与卡尔曼滤波是实现手段，不应成为用户可见的信息架构，也不应强迫所有交互都进入同一数学模型。

## 开题报告与现有实现的关键校正

### 机会约束公式

研究中假设用户可用时间为随机变量：

`T_max ~ Normal(mu, sigma^2)`

如果要求路线在至少 `1 - epsilon` 的概率下不超时：

`P(route_time <= T_max) >= 1 - epsilon`

正确的确定性等价约束为：

`route_time <= mu + sigma * Phi^-1(epsilon)`

也可写成：

`route_time <= mu - sigma * Phi^-1(1 - epsilon)`

原报告与旧代码写成了 `mu - sigma * Phi^-1(epsilon)`。当 `epsilon < 0.5` 时该值反而大于 `mu`，会把安全预算放宽而不是收紧。论文公式、代码和实验结果必须同步修正。

### 模糊表达不是只有时间方差

“大概四小时”可以映射为时间不确定性，但“随便走走”“想深入一点”“今天有点累”分别涉及节奏、探索深度和体力状态，不应全部压缩成一个 `sigma`。

建议将用户状态拆成：

- 硬约束：可用时间、必须去或不能去的地点、出发地、营业时间、无障碍需求。
- 软偏好：文化、自然、商业、景观、室内、教育和摄影。
- 当下状态：体力、情绪、节奏、拥挤容忍度、决策意愿。
- 交互状态：已接受、已拒绝、已完成、临时跳过和主动延长。

### 卡尔曼滤波的合理边界

卡尔曼滤波适合追踪连续、渐变的偏好，例如节奏逐渐变慢、文化兴趣持续增强。它不适合单独处理必须去某地、删掉某站或突然下雨等离散事件。

因此状态更新应采用混合机制：

- 连续偏好由状态空间模型更新。
- 明确命令由确定性事件处理器执行。
- 重大场景变化触发全局重规划。
- 路线小修改触发局部编辑和统一的距离、时间重算。

### 当前实现的算法规格

以下为代码中已落地的形式，可直接用于论文的方法章节。

**时间风险约束。** 令 `T` 为可用时间、`D` 为路线实际时长，`s = sqrt(sigma_T^2 + sigma_D^2)`。所有模型统一收敛为

`E[D] <= mu - kappa(epsilon) * s`

| `kappa(epsilon)` | 形式 | 依据 |
| --- | --- | --- |
| `gaussian` | `Phi^-1(1 - epsilon)` | 正态下的精确确定性等价 |
| `cvar` | `phi(Phi^-1(1 - epsilon)) / epsilon` | `CVaR_{1-eps}(Z) <= 0` 蕴含机会约束（Rockafellar & Uryasev 2000；Nemirovski & Shapiro, SIAM J. Optim. 17(4), 2006, 式 2.11） |
| `moment` | `sqrt((1 - epsilon) / epsilon)` | 仅用均值与方差的分布无关界（Cantelli / Scarf；Calafiore & El Ghaoui 定理 3.1） |
| `wasserstein` | `cvar` 再减 `theta / epsilon` | 1-型 Wasserstein 球半径 `theta` 下最坏 CVaR 的闭式增量 |

三者保守程度严格递增（`epsilon = 0.1` 时分别为 1.2816、1.7550、3.0000），有单元测试锁定。预算向下取整而非四舍五入，否则 0.1 分钟的上舍入即可让路线越过分位数。预算不可行时由 `TimeBudget.feasible` 显式报告，不再静默截断到 30 分钟。

**偏好状态估计。** 七维随机游走卡尔曼滤波（六个属性维 + 节奏维），`F = I`：

- 每个观测只携带它真正测到的维度，由 `H` 选择。此前把未测维度填充为“均衡”值，导致上报节奏会把属性估计拉回均衡、接受地点会把节奏拉回 0.5。
- 协方差用 Joseph 稳定形式 `P = (I - KH) P (I - KH)' + K R K'`，并对特征值做上下限截断，兼顾对称正定与“不会越来越自信却越来越错”。
- 归一化新息平方服从自由度为观测维数的卡方分布，离群观测按卡方分位数拒绝并反向放大 `P`，不再使用与维数无关的固定阈值。
- 打分权重按逆方差与模式基线融合：滤波不确定时让位基线，确信时覆盖基线。

**路线构造。** 选点与排序属于定向越野问题（Orienteering / TTDP），NP 难，采用“构造 + 改进”：宽度受限的束搜索构造，再对非锁定段做 2-opt 降低移动时间（参照 Vansteenwegen 等 2009 对 TOPTW 的插入 + 局部搜索框架）。束宽为 1 时退化为原贪心，因此不会更差。锁定站点视为偏好而非硬约束：当收紧后的预算容纳不下锁定前缀时按序截断，保证输出路线始终满足机会约束。

### 合成对话的定位

800 条合成对话适合用于原型训练、覆盖测试和消融实验，不能直接证明真实用户价值。后续应补充两类数据：

- 少量高质量人工标注对话，用于检验意图、调整类型和偏好方向。
- 真实可用性测试日志，用于检验路线接受率、调整次数、保存率和实际停留误差。

## 已建立的统一工程基线

当前工作区已经新增 `tripsense` 工程：

- 北京、上海清洗数据及距离图统一进入 `data`。
- 新增不依赖外部大模型的中文本地意图基线。
- 修正机会约束分位数方向。
- 候选点依据当前城市的距离图筛选，不再使用写死的北京经纬度边界。
- 用户场景类别真正进入候选过滤。
- 路线编辑后可统一重算相邻路程、总时长和提醒状态。
- 新增 SQLite 旅程记录，可保存路线、完成状态、实际停留时间和备注。
- 预留 FastAPI 的规划与旅程记录接口。
- 11 项离线测试已经通过。

## 下一阶段实现顺序

### 第一优先级 景点质量与候选治理

- 建立地标、主景点、子景点和商业装置的明确层级。
- 修复上海出现“高热度但不适合作为旅行核心站点”的候选问题。
- 增加景点可解释标签、可信来源和内容质量评分。
- 为不同路线模式建立独立候选规则，而不是只调整同一套分数。

### 第二优先级 路线组合与动态编辑

- 从单步贪心升级为束搜索或小规模动态规划，避免高分长时景点占满预算。
- 同时优化地点价值、移动成本、类别多样性、时间风险和用户状态。
- 完成加点、删点、替换、延长停留和临时休息的统一编辑协议。
- 每次编辑后重新验证相邻路程、营业时间和超时概率。

### 第三优先级 产品闭环

- 将现有原型拆成真实前端组件。
- 接通离线规划 API，保证没有 Key 也能完整演示。
- 把时间滑块、智能提醒与后端重新计算连接。
- 接通路线保存、打勾、实际停留和备注。
- 再增加可选的大模型语义增强与产品语气生成。

### 第四优先级 研究评估

- 修正论文公式后重跑 CCP 与 DRCCP 实验。
- 将约束满足率目标设为与 `1 - epsilon` 一致。
- 分开评估意图分类、调整类型、偏好方向、路线质量和记录预测。
- 检查卡尔曼误差与协方差是否一致，避免模型误差上升但置信度反而提高。

## MVP 成功标准

- 用户用一句自然语言即可得到一条合理路线，并能理解推荐原因。
- 用户提出局部修改时，系统保留此前上下文且不偷偷改变无关部分。
- 时间滑块变化后，路线总时长和提醒实时一致。
- 北京和上海均不会出现跨城候选或明显不合理的核心景点。
- 没有外部 API Key 时仍能完成规划、调整、保存和记录。
- 真实测试用户能完成任务，并愿意保存或继续使用路线。
